## Key Implementation Notes

Cases use GUID strings and actors use stable string IDs to preserve secure partition/ownership semantics;
bank activity records have integer IDs. This intentionally differs from a universal integer model-ID convention.
Amounts use integer cents, not floating-point accounting. Balance snapshots are not reconstructed from transactions.
App-owned ETag transitions, not model text, authorize human claim/reply/close.
Saved agent versions are captured from creation outputs and persisted as installation configuration.
Only the installer uses Azure CLI user credentials; the deployed app uses managed identity for all Azure calls.
Session keys use a restricted single-worker App Service persistent directory with platform encryption.
Production/scale-out key management, private networking, multilingual risk rules and contact-center integration
require separate design and consent.
