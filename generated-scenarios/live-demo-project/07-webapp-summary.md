## Application

.NET 10 Razor Pages, Azure.Identity 1.17.1 and the documented Foundry REST v1 agent/Responses contract.
Direct REST is intentional: the verified v1 function-selection envelope is small and avoids unnecessary
preview SDK dependencies. It is the only external service HTTP call; there is no external web retrieval.
The runtime credential is `ManagedIdentityCredential`, never a service key or a developer token.

Business entities: approved knowledge entry and support conversation, plus local app accounts.
Ten company-authored synthetic entries cover a prospective/existing brokerage customer's service needs.
The exact catalog-derived company and two mapped people are shared by login and content.

Routes: local sign-in, customer support, representative desk, access-denied and explicit error page.
Razor forms supply CSRF tokens, field limits and server-side role checks.
Account hashes and five-failure/five-minute lockout state are durable.
Secure HttpOnly SameSite cookies have a 30-minute non-sliding lifetime; session keys persist.

Theme: restrained deep-green brokerage styling, neutral surfaces, Fluent-style semantic tokens,
clear typographic hierarchy and visible keyboard focus; text navigation needs no decorative icons.
No external fonts, scripts, trackers or UI CDN are used.
The 390px mobile test asserts no horizontal overflow.
Error, empty queue, pending human and assigned-human states are visible and text-labeled.

Known demo limitations: one hosting instance, file-backed state, asynchronous polling and no real trading system.
There is no model-success simulation mode.
Real Foundry calls still require deployment and live acceptance.
